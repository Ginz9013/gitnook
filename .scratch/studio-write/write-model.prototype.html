拖一張卡片改狀態時，畫面該相信誰：你的手，還是每兩秒回來一次的伺服器？

這個 prototype 要回答的問題：

studio 目前是唯讀的，每 2 秒問一次 /hash，值變了就整頁重載。 一旦開放寫入並加上拖拉，整頁重載就不能用了 —— 拖到一半被重載、抽屜開著被重載。 取代它的東西必須同時處理三件事：樂觀更新（放手就動）、 輪詢調和（伺服器才是真相）、以及 append-only CRDT （你的 op 一定寫得進去，但可能在 LWW 決勝時輸掉）。

按下面的按鈕，把這三件事的各種交錯順序實際跑一遍。 如果這個模型撐得住，那它在 SSR 和 React 底下是同一份程式碼 —— 框架選型就跟狀態同步無關，只剩渲染方式要選。這正是要驗證的。
